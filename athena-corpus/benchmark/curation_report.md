## 2. How snippets were chosen (funnel)

Candidate units = top-level functions/classes/interfaces/enums plus each method of a class (all languages, 4122 units). A unit is dropped when: 1354 shorter than 6 lines; 473 longer than 40 lines; 222 contain an identifier that fails a core naming rule (the *standard* snippet must be compliant); 416 have fewer than 2 renameable target identifiers; 1 overlap a parse error; 5 yield fewer than 2 targets with a verified violation; 6 are duplicates of an already chosen snippet.

Target identifiers rejected for renaming safety: name_in_fstring_expression 267, shorthand_property 209, code_like_name_in_string 98, name_in_multiple_namespaces 65, no_verified_violation 52.

Rename verification: 8024 candidate renames re-parsed with an identical syntax-tree shape; 71 rejected because the shape changed.

## 4. Rule policy

Core rules (gate + injection targets) per (language, kind) are listed in `curation/rules.py` (`CORE`); each is verified at start-up to be retrievable from the ontology for that (language, kind) and cross-checked against `graph_loader.get_applicable_rules` (80 pairs, identical). Rules **not** used as core rules:

| Rule | Reason |
|---|---|
| PEP8-EXCEPTION-ERROR-SUFFIX | conditional: only exception classes (applied at gate time when a base class name ends in Error/Exception; never an injection target) |
| PEP8-PARAM-KEYWORD-TRAILING-UNDERSCORE | conditional: only when a parameter name would collide with a keyword |
| PEP8-FIELD-NONPUBLIC-UNDERSCORE | conditional: non-public attributes only; its casing+prefix attributes are mutually inconsistent for the mechanical checker |
| PEP8-FIELD-NAME-MANGLE | conditional: name-mangling attributes only (MAY) |

## 5. Findings and limitations (read before using the numbers)

1. **Ontology gap - parameters.** Ontology v1 has no ordinary-parameter casing rule for Python or JavaScript. Python parameters are gated and attacked through `PEP8-PARAM-SELF-CLS` (the only parameter rule carrying `casing=snake_case`; 133 violation files carry a `ruleCaveat`). JavaScript parameters only get the descriptive-name rule (184 files), so a JS parameter named `user_id` counts as compliant. Adding `PEP8-PARAM-SNAKE` / `AIRBNB-PARAM-CAMEL` to the ontology would fix both.
2. **Injection types.** The project's `violation_injector.py` only abbreviates for rules with `minLength` and only strips prefixes/suffixes for rules that carry them, so the set is casing_swap (2356) and forbidden_pattern (601); there are no abbreviation-style violations for Python/Java/C#/TypeScript. Core rules with targets but no constructible violation: DOTNET-NO-HUNGARIAN-NO-UNDERSCORE, GJAVA-FIELD-NO-HUNGARIAN, GJAVA-IDENT-ASCII (forbidden-prefix / ASCII patterns the injector cannot build). Core rules with no snippet of their identifier kind in the final set (kind rare in the pool): AIRBNB-CLASS-PASCAL, AIRBNB-CONST-UPPER, AIRBNB-FIELD-NO-UNDERSCORE, GTS-CONSTANT-CASE, GTS-ENUM-MEMBER-CONST, GTS-ENUM-PASCAL, GTS-FIELD-CAMEL.
3. **Small TypeScript/JavaScript pools.** Only 5 TypeScript and 7 JavaScript repos have clean candidates; most TS files are React components (exempt: PascalCase functions returning JSX are not covered by Google TS Style), so TypeScript snippets are dominated by interfaces/properties/variables and contain almost no classes.
4. **Gate strictness.** A snippet is kept only if *every* checked identifier in it passes its core rules, so snippets skew toward code that already follows each standard (see section 3 for how often real code does not).
5. **Not extracted:** module/package/namespace names, type parameters, lambda parameters, destructured names, Python `self`/`cls`, dunder names, C# non-public fields (no rule in the ontology), Java `static final` fields of non-primitive/String type (deep immutability not decidable), React components, framework-mandated names are kept as real violations.
6. **Rename scope.** Violations rename every occurrence of the identifier inside the snippet (same namespace: local vs member vs type); code-like multi-word names are also rewritten in comments/docstrings so the original name does not leak; targets whose name appears in a string literal, a Python f-string expression, or JS/TS shorthand property are not used. Because a snippet is an excerpt, references outside it are unknown.
7. **C# booleans.** Following the pilot (`IsConnected` as `boolean_variable`), bool-typed properties/fields/locals use kind `boolean_variable`; they are gated by the boolean rule *and* the base kind's rule, but violations only target the boolean rule (the only one retrievable for that kind).
8. **Schema additions.** `standardId` uses the ontology ids (`PEP8`, `GOOGLE_JAVA`, `DOTNET_DESIGN`, `GOOGLE_TS`, `AIRBNB_JS`, as in the pilot code), not the lower-case ids written in benchmark_schema.md. Additive fields: snippet `provenance`; violation `occurrencesRenamed`, `commentOccurrencesRenamed`, `ruleCaveat`.

## 6. Checks performed

- `validate_benchmark.py` (independent of the parsers): schema; every listed identifier occurs in its code and passes all core rules of its kind; `codeContext` equals the dedented excerpt of the pinned source bytes in `corpus/<lang>/<file>.md`; for each violation the original passes and the injected name fails its rule with the recorded reasons, the rule is retrievable for the kind, `injectionMethod` reproduces, and the two code contexts differ only by original->injected identifier text; indexes match files.
- `syntax_check.py`: every snippet and every violated context parses standalone (Python `ast`; others tree-sitter, class members wrapped in a class).
- Corpus integrity: every corpus file's git blob SHA-1 recomputed during curation equals `corpus_index.tsv` (0 mismatches).
- Determinism: two full runs produced byte-identical snippets/violations.

## 7. Comment units (Task C, RQ2)

`make_comment_units.py` builds one comment-generation unit per curated snippet whose main declared
entity is a `function`, `method` or `class` (`interface`/`enum`/`const`/`constructor` skipped), plus
extra units mined from the 792-file corpus for languages with fewer than 30 such units. Nothing here
is an LLM; two full runs produce byte-identical output. Independent check: `validate_comment_units.py`
(standard library only) — 0 errors.

Dev/test split (same per-snippet hash split as the rename task; a comment unit shares its parent
snippet's split so a unit never crosses the dev/test boundary): 31 dev / 89 test overall
(csharp 8/22, java 7/13, javascript 3/3, python 9/28, typescript 4/23).

Candidates considered and rejected, with reasons (a candidate is every function/method/class-kind
unit of a curated snippet, or of a top-up scan over the corpus, before a reference comment is
found and validated):

| Reason | Count |
|---|---|
| No doc comment found directly above/inside the declaration | 600 |
| Kind excluded (interface / enum / const / constructor / kind unresolved) | 61 |
| Ordinary `//` or single-star `/*...*/` comment (not a doc comment) | 4 |
| Comment shorter than 3 words / 20 characters | 2 |

No candidate was rejected for containing a UTF-8 surrogate (`errors="surrogateescape"` handling of
the two known non-UTF-8 corpus files, both C#): the bad byte in each falls either inside an ordinary
`//` comment far from any candidate's scan window, or inside a constructor's XML doc comment (constructors
are excluded by kind before a comment is even looked for).

Reference comment location: for Python the docstring is the unit's own first body statement, so it
comes from the snippet's already-dedented `codeContext`; for Java/C#/TypeScript/JavaScript the doc
comment sits **above** the snippet's own line range in the pinned source, so it is read from the
pinned corpus file directly. Checked empirically for all 120 units: the leading comment was never
found already embedded inside a non-Python snippet's `codeContext` (0 occurrences) — confirming the
curation pipeline's unit boundaries start exactly at the declaration, not its comment.

`signature`/`expectedElements` (params count, whether the unit's own body — not a nested
function/lambda/class — returns a value or raises/throws) are derived from the code only, via `ast`
for Python and tree-sitter elsewhere, and used to scope which `requiredElements` of a CommentRule
apply to a given unit (e.g. a void method is not held to `@return`).

not a benchmark bug, and it is reported as such rather than adjusted away.
